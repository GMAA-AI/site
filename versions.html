How versions work

Every version is cited on two axes together: the package version (the engine artifact) and the canon pin (the specification version the artifact ships and conforms to). Every content change is a new version, and nothing is ever rebuilt in place under an existing label. Verify every download against its fingerprints before use.

How it ships

One release, six loose files, one sealed engine.

Loose at the repository root, readable before you download anything: the README in Markdown and as rich text (the argument and the quick start), the license, MANIFEST.sha256 and PROVENANCE.tsv (the fingerprint and the source of every file in the engine, the same two files that ship inside it), and SHA256SUMS, which fingerprints all of them plus the engine zip. No specification PDF ships with this release. The specification is inside the engine and on canon.html.

One sealed download, the engine. The machinery you run ships as a single sealed zip: the governance scripts, agent definitions, contracts, schema, the adopter entry documents (the adoption cover, the walkthrough for getting started and the operator chat setup, each with a copy in rich text), the operator guide as a PDF, the changelog, the citation file, and the specification itself, canon v1.6.8, at the package root as GOVERNED_MULTI_AGENT_ARCHITECTURE_v1_6_8.md. The zip carries its own MANIFEST.sha256 covering every file, including the canon, so the engine and the exact specification it conforms to travel and verify as one artifact.

The split follows the licensing. The specification is free under CC BY 4.0 and is the target for citing by version, readable at canon.html without downloading the engine. The engine ships with its source available under Apache 2.0 with the Commons Clause, which is not an open source license under the OSI definition. It is free to use, modify, and redistribute, but not to sell or offer as a paid service. It is the one controlled artifact, and the canon inside the zip is the copy it pins.

Upgrading. Holders of any earlier blank package, v2.5.2 through v2.5.7, replace it in full and verify again against SHA256SUMS. Instantiated projects adopt v2.7 as a change inside a set their apex ratifier ratifies. It is a new extraction, and v2.5.7 slot fills do not carry over. There is no patch path, deliberately: partial trees cannot be verified by fingerprint, and the absence of a hotfix vehicle is a governance statement, not a missing feature.
